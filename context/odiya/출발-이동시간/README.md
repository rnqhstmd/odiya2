- 관련 레포: odiya-ios, odiya-api

---

## 핵심 개념

odiya의 핵심 차별 기능. 약속 시간에서 이동시간과 버퍼를 역산하여 출발 알림을 보낸다.
odiya는 길찾기 앱이 아니라 **"언제 출발해야 해?"**만 알려주는 앱이다. 경로 데이터(폴리라인 등)는 저장하지 않고, **소요시간(분)만** 계산·저장한다.

### 역산 공식

```
출발알림시각 = 약속시간 - API소요시간 - 주차버퍼(해당시) - 여유시간
```

- **API소요시간**: 이동수단별 API로 계산한 예상 소요 시간
- **주차버퍼**: 자동차(주차) 선택 시에만 적용 (기본 10분, 사용자 조절 가능)
- **여유시간**: 모든 이동수단 공통 (기본 5분, 사용자 조절 가능)

---

## 사전 계산 & 저장

약속 생성/변경 시 **즉시 API를 호출**하여 소요시간을 계산하고 저장한다. 실시간 반복 호출을 최소화한다.

### 저장 데이터

| 필드 | 예시 | 설명 |
|------|------|------|
| `duration_minutes` | 42 | API 반환 소요시간 |
| `transport_type` | `CAR_PARKING` | 이동수단 |
| `calculated_at` | 2026-03-03T14:00:00 | 계산 시점 |
| `departure_alert_at` | 2026-03-03T15:08:00 | 역산된 출발 알림 시각 |

경로 데이터, 폴리라인, 중간 경유지는 저장하지 않는다.

### 계산 트리거

| 시점 | 동작 |
|------|------|
| 약속 생성 | 출발지 + 약속장소 + 이동수단 확정 → 즉시 API 호출 → 소요시간 저장 → 출발 알림 스케줄 등록 |
| 약속 변경 (장소/시간) | 소요시간 재계산 → 출발 알림 스케줄 갱신 |
| 출발지 변경 | 해당 약속의 소요시간 재계산 |
| 이동수단 변경 | 해당 약속의 소요시간 재계산 |

## 출발지 등록

사용자는 자주 사용하는 출발지를 등록할 수 있다.

| 항목 | 설명 |
|------|------|
| 집 | 기본 출발지 |
| 회사 | 보조 출발지 |
| 기타 | 사용자가 직접 추가하는 출발지 |

- 약속별로 출발지를 선택하거나, 기본 출발지가 자동 적용된다.
- 출발지 미등록 시 출발지 등록을 유도하는 알림을 보낸다.

## 이동수단 (4종)

API 조사 결과, 이동수단별로 사용하는 API가 다르다.

| 이동수단 | enum | API | 소요시간 계산 |
|----------|------|-----|--------------|
| 자동차 (주차) | `CAR_PARKING` | 카카오모빌리티 자동차 길찾기 | API 소요시간 + 주차버퍼 |
| 자동차 (픽업) | `CAR_PICKUP` | 카카오모빌리티 자동차 길찾기 | API 소요시간만 |
| 대중교통 | `TRANSIT` | ODsay 대중교통 API | API 소요시간 그대로 (door-to-door) |
| 도보 | `WALKING` | 직선거리 기반 추정 | 거리 / 분속 80m |

### 자동차 — 주차 vs 픽업

자동차 이동 시 **"주차하러 가는 건지, 픽업하러 가는 건지"**에 따라 소요시간이 크게 다르다.

| 구분 | 주차 (CAR_PARKING) | 픽업 (CAR_PICKUP) |
|------|-------------------|-------------------|
| 주차장 탐색 | ~3분 | 없음 |
| 주차 행위 | ~3분 | 없음 |
| 주차장→약속장소 도보 | ~4분 | 없음 |
| 추가 버퍼 | **기본 10분** (사용자 조절 가능) | **0분** |
| 사용 예 | 약속장소에서 만남 | 친구를 차로 픽업, 약속장소 앞에서 하차 |

### 대중교통

- ODsay API는 **door-to-door**로 계산 (출발지 도보 → 탑승 → 환승 → 하차 → 도착지 도보 모두 포함)
- API 반환값을 그대로 사용. 추가 버퍼 불필요.

### 도보

- 별도 API 호출 없이 **직선거리 기반 추정** (거리 / 분속 80m)
- 정밀한 도보 경로가 필요 없음. "대략 몇 분 걸리는지"만 알면 충분.
- 사용자가 약속별로 이동수단을 선택한다. 미선택 시 기본 이동수단(사용자 설정)이 적용된다.

## 사용자 설정

| 설정 | 기본값 | 적용 범위 | 설명 |
|------|--------|-----------|------|
| 기본 이동수단 | `TRANSIT` | 전체 약속 | 약속 생성 시 미선택이면 적용 |
| 주차 버퍼 | 10분 | `CAR_PARKING`만 | 주차 탐색 + 주차 + 도보 시간 |
| 여유 시간 | 5분 | 모든 이동수단 | "넉넉히 나가고 싶은" 정도 |

> 설계 원칙: **5분 일찍 도착하는 건 OK, 5분 늦는 건 실패.** 버퍼는 항상 넉넉한 쪽으로.

## 당일 재계산

자동차만 당일 재계산한다. 대중교통/도보는 시간이 거의 변하지 않으므로 재계산하지 않는다.

| 이동수단 | 당일 재계산 | 이유 |
|----------|------------|------|
| 자동차 (주차/픽업) | O | 교통 상황 변동 |
| 대중교통 | X | 시간표 기반, 거의 고정 |
| 도보 | X | 완전 고정 |

### 자동차 재계산 주기

| 시점 | 재계산 간격 |
|------|-------------|
| 약속 1시간 전~ | 30분 간격 |
| 약속 30분 전~ | 10분 간격 |

### 변동 알림

- 재계산 결과 이동시간이 **10분 이상** 변동되면 참여자에게 알림을 보낸다.
- 출발 알림 시각도 함께 갱신된다.

## 이동시간 캐시

- Redis에 이동시간 계산 결과를 캐시한다.
- 캐시 키: `{출발지}:{약속장소}:{이동수단}`
- TTL: 자동차는 재계산 간격에 맞춰 동적 설정, 대중교통/도보는 24시간

## API 선택 근거

카카오모빌리티 + ODsay 조합으로 API를 구성한다. 카카오 로그인·지도·장소 검색과 동일한 카카오 API 키를 사용하므로 관리가 단순하다.

| 이동수단 | 선택한 API | 선택 이유 |
|----------|-----------|-----------|
| 자동차 | 카카오모빌리티 | 무료 할당량 최대 (일 1만건), 실시간 교통 반영 |
| 대중교통 | ODsay | 유일한 대중교통 전문 API. 일 1,000건 무료 (6개월) |
| 도보 | 직선거리 추정 | API 호출 없이 충분. 할당량 절약 |

상세 API 현황 및 비용은 [지도](../지도/) 문서 참조.

### 이동시간 계산 (내부 서비스 — Controller 없음)

약속 생성/수정/출발지 변경 시 서버 내부에서 자동으로 이동시간을 계산한다. 별도 API 엔드포인트는 없고, 다음 API의 부수 효과로 실행된다:

| 트리거 API | 계산 동작 |
|-----------|----------|
| `POST /api/v1/appointments` | 출발지 있으면 즉시 계산 |
| `PATCH /api/v1/appointments/{id}` | 장소/시간 변경 시 재계산 |
| `PATCH /api/v1/appointments/{id}/departure` | 출발지/이동수단 변경 시 재계산 |

**이동수단별 호출 API:**

| 이동수단 | 외부 API | 비고 |
|----------|---------|------|
| CAR_PARKING | 카카오모빌리티 자동차 길찾기 | + 주차버퍼 |
| CAR_PICKUP | 카카오모빌리티 자동차 길찾기 | 버퍼 없음 |
| TRANSIT | ODsay 대중교통 API | door-to-door |
| WALKING | 직선거리 / 분속 80m | API 미사용 |

**캐시 (Redis):**

| 키 패턴 | TTL | 설명 |
|---------|-----|------|
| `travel:{출발지좌표}:{도착지좌표}:{이동수단}` | 자동차: 재계산 간격, 대중교통/도보: 24시간 | 동일 구간 중복 호출 방지 |
